# 火羽实时字幕 App —— 服务器端「版本检测」接口需求

> 给服务端同学：App 需要新增「启动时检测是否有新版本」功能，需要你们提供一个**只读的版本信息接口**。
> 只有一个新接口，不改动现有任何逻辑；另外请确认 APK 下载链接（`/app`）在更新后同步替换。

---

## 一、需要实现的东西一览

| # | 内容 | 说明 |
|---|---|---|
| 1 | **`GET /api/version`** | 新增，返回 JSON，告诉客户端「最新版本号」和「下载地址」 |
| 2 | **`GET /app`** | 已存在，无需新增；但**每次发版后要把该文件替换成新 APK**（客户端点「升级」就下载它） |
| 3 | **镜像同步** | 下面 4 台服务器都要实现 `GET /api/version`（原因见末尾） |

**接口必须免口令访问**（不需要 `?k=`）。若你们的口令中间件会拦截 `/api/*`，请把 `/api/version` 加入白名单；
或者改用路径 `GET /app/version`（客户端两个路径都会尝试，哪个能用用哪个）。

---

## 二、接口定义

### `GET /api/version`

- **方法**：`GET`
- **是否需要口令**：**否**（公开只读）
- **可用备选路径**：`GET /app/version`（返回内容完全一致，客户端会依次尝试这两个路径）
- **客户端会附带的参数**（可忽略，也可以校验）：
  - `k`（string，可选）：当前口令，例如 `hy`

**响应 200，`Content-Type: application/json`**

```json
{
  "platform": "android",
  "versionCode": 3,
  "versionName": "1.2",
  "minVersionCode": 1,
  "downloadUrl": "http://123.60.104.22:6006/app",
  "force": false,
  "title": "火羽实时字幕 1.2",
  "notes": "1. 新增启动时自动检测新版本\n2. 网址变化时字幕服务器自动跟随切换\n3. 修复若干问题",
  "sizeBytes": 41234,
  "sha256": "9f2c...（可选，APK 的 sha256）",
  "publishedAt": "2026-10-16T15:00:00+08:00"
}
```

### 字段说明

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `versionCode` | int | **是** | 最新 APK 的 `versionCode`。**客户端就靠它跟本机比较**，必须与 APK 里 `AndroidManifest` 的 `versionCode` 完全一致 |
| `versionName` | string | **是** | 展示用版本号，如 `"1.2"` |
| `minVersionCode` | int | 否，默认 `0` | 低于该版本**强制升级**（只有「立即升级」按钮，点返回键也不关闭） |
| `downloadUrl` | string | 否 | 点「升级」要打开的地址。**不填则客户端默认用 `{当前服务器}/app`**，所以可以省略 |
| `force` | bool | 否，默认 `false` | `true` 时本次强制升级（等价于把 `minVersionCode` 设成本机版本以上） |
| `title` | string | 否 | 弹窗标题，默认客户端拼「发现新版本 x.y」 |
| `notes` | string | 否 | 更新说明，支持 `\n` 换行，在弹窗里展示 |
| `sizeBytes` | int | 否 | APK 大小，展示成「约 40 KB」 |
| `sha256` | string | 否 | APK 的 sha256，客户端可用来校验下载完整性 |
| `publishedAt` | string | 否 | 发布时间，ISO 8601 |

### 出错时

- 返回 404 / 500 / 超时 / 非法 JSON → **客户端一律静默忽略**，不影响 App 使用，也不弹窗。
- 所以接口临时挂掉是安全的，不会打扰用户。

### 缓存建议

```
Cache-Control: no-store
```
或 `max-age=60`。避免 CDN/反向代理把版本信息缓存住，导致发版后客户端查不到。

## 三、版本号从哪来？（两种实现，任选）

> 核心要求只有一条：**`versionCode` 必须跟着 APK 一起更新，不能和实际包里的版本号不一致。**

### 方案 A（推荐）：发版时写一个 `app_version.json`，接口直接读它

服务器上放一个文件，发版脚本负责覆盖它：

`app_version.json`
```json
{
  "versionCode": 3,
  "versionName": "1.2",
  "minVersionCode": 1,
  "force": false,
  "title": "火羽实时字幕 1.2",
  "notes": "1. 新增启动时自动检测新版本\n2. 修复若干问题",
  "publishedAt": "2026-10-16T15:00:00+08:00"
}
```

### 方案 B（更省心）：服务端启动时自动解析 APK，不会忘记改

用 `aapt2` 从 APK 里直接读出真实版本号：

```bash
aapt2 dump badging 火羽实时字幕-v1.2.apk | head -1
# package: name='com.huoyu.livesub' versionCode='3' versionName='1.2' ...
```

## 四、服务端参考实现（FastAPI，可直接粘）

> 与现有 `/app` 放在同一个 FastAPI 应用里即可。

```python
import os
import json
import subprocess
from fastapi import FastAPI, Request
from fastapi.responses import JSONResponse

app = FastAPI()  # 你们现有的 app

# ---- 配置：APK 文件路径 & 版本信息文件路径 ----
APK_PATH = os.environ.get("APP_APK_PATH", "static/huoyu-livesub.apk")
VERSION_FILE = os.environ.get("APP_VERSION_FILE", "app_version.json")


def _read_version_file() -> dict:
    """方案 A：读发版脚本写好的 app_version.json"""
    try:
        with open(VERSION_FILE, "r", encoding="utf-8") as f:
            return json.load(f)
    except Exception:
        return {}


def _read_version_from_apk() -> dict:
    """方案 B：从 APK 里解析真实 versionCode / versionName（需要 aapt2 在 PATH 里）"""
    try:
        out = subprocess.check_output(
            ["aapt2", "dump", "badging", APK_PATH],
            stderr=subprocess.DEVNULL, timeout=10,
        ).decode("utf-8", "ignore")
        first = out.splitlines()[0]
        # package: name='com.huoyu.livesub' versionCode='3' versionName='1.2' ...
        def pick(key):
            for part in first.split():
                if part.startswith(key + "="):
                    return part.split("=", 1)[1].strip("'\"")
            return None
        vc = pick("versionCode")
        vn = pick("versionName")
        if vc:
            return {"versionCode": int(vc), "versionName": vn or "0.0"}
    except Exception:
        pass
    return {}


def load_app_version() -> dict:
    v = _read_version_file()
    if not v.get("versionCode"):
        v = {**_read_version_from_apk(), **v}
    return v


@app.get("/api/version")
async def api_version(request: Request):
    v = load_app_version()
    base = str(request.base_url).rstrip("/")          # http://123.60.104.22:6006
    body = {
        "platform": "android",
        "versionCode": int(v.get("versionCode", 0)),
        "versionName": str(v.get("versionName", "0.0")),
        "minVersionCode": int(v.get("minVersionCode", 0)),
        "downloadUrl": v.get("downloadUrl") or f"{base}/app",
        "force": bool(v.get("force", False)),
        "title": v.get("title", ""),
        "notes": v.get("notes", ""),
        "sizeBytes": v.get("sizeBytes"),
        "sha256": v.get("sha256"),
        "publishedAt": v.get("publishedAt"),
    }
    return JSONResponse(content=body, headers={"Cache-Control": "no-store"})


# 备选路径，内容完全一致（防止 /api/* 被口令中间件拦截）
@app.get("/app/version")
async def app_version_alias(request: Request):
    return await api_version(request)
```

**注意**：如果你们的口令校验中间件是拦截 `/api/*` 前缀的，记得把 `/api/version` 放行，
或者只保留 `/app/version` 这个别名路径（客户端两个都会试）。

### 发版脚本示例（替换 APK + 更新版本信息）

```bash
#!/bin/bash
set -e
NEW_APK="火羽实时字幕-v1.2.apk"

# 1. 用 aapt2 读出真实版本号
INFO=$(aapt2 dump badging "$NEW_APK" | head -1)
VC=$(echo "$INFO" | sed -n "s/.*versionCode='\([0-9]*\)'.*/\1/p")
VN=$(echo "$INFO" | sed -n "s/.*versionName='\([^']*\)'.*/\1/p")

# 2. 替换下载文件（保持 /app 指向的文件是最新的）
cp "$NEW_APK" static/huoyu-livesub.apk

# 3. 更新版本信息文件
cat > app_version.json <<JSON
{
  "versionCode": ${VC},
  "versionName": "${VN}",
  "minVersionCode": 1,
  "force": false,
  "title": "火羽实时字幕 ${VN}",
  "notes": "请填写本次更新说明",
  "sizeBytes": $(stat -c%s "$NEW_APK"),
  "publishedAt": "$(date -Iseconds)"
}
JSON

echo "done: versionCode=${VC} versionName=${VN}"
```

## 五、为什么要 4 台都实现（重要）

App 内置了字幕服务器白名单，会在网址变化时自动切换服务器：

```
http://106.15.35.175:6006/
http://123.60.104.22:6006/
http://123.60.104.22:6007/
http://8.133.231.186:6006/
```

**客户端是用「当前正在使用的那个服务器」去查版本的**（`GET {当前服务器}/api/version`）。
所以这 4 台只要有一台会被用户用到，就需要实现该接口；否则用户切到没实现的服务器时，升级检测就静默失效。

同理，`/app` 下载文件也建议每台都放一份最新 APK（或者 4 台的 `downloadUrl` 都指向同一台）。

---

## 六、客户端这一侧会怎么做（供你们对照）

1. App 启动时（以及每次从后台回到前台）请求 `{当前字幕服务器}/api/version`，超时 5 秒。
2. 拿到 `versionCode`，与本机已安装的 `versionCode` 比较：
   - `服务器 versionCode > 本机 versionCode` → 弹窗提醒升级。
   - 否则或请求失败 → 什么都不做。
3. 弹窗内容：标题（`title` 或「发现新版本 x.y」）+ 更新说明（`notes`），两个按钮：
   - **「立即升级」** → 用系统浏览器/下载器打开 `downloadUrl`（默认 `{当前服务器}/app`），直接下载最新 APK。
   - **「稍后更新」** → 关闭弹窗，不影响继续使用。
4. 若 `force = true` 或本机 `versionCode < minVersionCode` → 隐藏「稍后更新」，只能升级。
5. 每次打开 App 只要仍是旧版本，**都会再次弹窗**。
6. 网络失败/接口不存在 → 静默跳过，绝不弹窗、绝不阻塞启动。

---

## 七、最小可行版本（如果只想先跑起来）

只需要两个字段，其余全可省略：

```json
{ "versionCode": 3, "versionName": "1.2" }
```

客户端会自动把下载地址兜底成 `{当前服务器}/app`，标题自动拼「发现新版本 1.2」。
